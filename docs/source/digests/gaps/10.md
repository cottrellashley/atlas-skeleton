### 2.3 The procedure the sources imply

What the sources fix is cited; anything the build must choose is marked.

1. **Build once and freeze:**
   - `atlas` (CLI): `go -C clients/cli build ./cmd/atlas`
   - `atlas-engine`: `go -C sdk/go build ./cmd/atlas-engine`
   - fiatlas, with that engine
   - `@atlas/sdk` (Node)

   The build commands are those of conftest.py:17-31. Record the client versions: each is `0.2.0` (assemble.go:62-67; sdk/go/client.go:35; clients/node/package.json). ATLAS-VERSION-004 asks that the release count be zero (03:545).
2. **Start the gateway without the capability:** `gateway-local -listen 127.0.0.1:0 -addr-file <f> -exclude portfolio.holdings-dates@v1 -catalog <dir>` (flags from gateway-local/main.go:49-54).
3. **Before the add, from each frozen client:**
   - `catalog` and `search` do not list it;
   - a `call` to `portfolio.holdings-dates@v1:fetch` reaches the gateway, which answers `not_found`. The client must look the address up with `atlas.describe` and must not refuse it itself (09-7:105).

   The live raw-HTTP test expects `not_found` (journey_test.go:382).
4. **Add it.** Two readings, both spec-backed; see A6:
   - **(hot)** copy `profiles/portfolio.holdings-dates@v1.json` and `views/portfolio.holdings-dates@v1.json` into `<dir>`. The *same long-lived* client sessions must then see it "on its next search or call, with no restart" (09-7:105);
   - **(deploy)** restart the gateway without `-exclude`, i.e. "Deploying a gateway with a new capability" (OV:91), as pass 1 did (§2.1).
5. **After the add, with the same binaries, in the CLI, Python and Node:**
   - `whoami`;
   - `search` with words from the guide (choose and record the query);
   - `guide portfolio.holdings-dates@v1` (or `guide portfolio.holdings-dates`);
