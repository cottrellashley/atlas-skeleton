## 0. Verdict

It is a real gap. The live tree answers part of it, and five things stay open:

1. **Whether P2-8 still stands** for Cosmos DB, Blob, Key Vault and Log Analytics. REVIEW.md cancels only its Service Bus part (§2).
2. **No explicit refusal for idempotency, operations or budgets.** `cmd/gateway` wires no store for any of them. Nothing refuses at start or at registration a capability that would need one (§4, rows 4-6).
3. **The cursor key falls back silently to a random key** when it is not configured (§4, row 7).
4. **The audit sink fails every call when stdout is a pipe.** I proved this on this machine (§5, D-1).
5. **The layer check does not enforce P2-4's split, and it fails today** (§6).

The tree has taken the reading that I call (c) in §2: real adapters for the journey's ports, with no Azure SDK. Policy comes from a file, audit goes out as JSON lines, secrets come from environment variables, and the warehouse is reached through `database/sql` with no driver linked. Neither REVIEW.md nor `docs/pass-2/ASSUMPTIONS.md` records this reading (A-001..A-030 are protocol readings only, ASSUMPTIONS.md:9-40).

## 2. Does P2-8 still stand?

**OVERRIDDEN BY REVIEW (R10, R16): Service Bus.** REVIEW.md:15 defers "Handoff, events and Service Bus", so P2-8's Service Bus adapter and P2-7 are **DEFERRED**.

**OVERRIDDEN BY REVIEW (step 5): the Entra On-Behalf-Of half.** REVIEW.md:33 puts "delegated identity" out of reach. PLAN §4's Entra row lists "MSAL Go (OBO)", so OBO is **DEFERRED**. Token verification is not delegated identity, so it stays **IN SCOPE**.

**AMBIGUOUS: Cosmos DB, Blob, Key Vault and Log Analytics.** REVIEW.md names none of them. The possible readings:
- **(a) P2-8 stands.** REVIEW.md governs PLAN only "where the two disagree" (:5), and it keeps "fakes behind real adapters" (:21). PLAN:11 wants "an adapter that is already written and tested". Under this reading, write `azcosmos`, `azblob`, `azsecrets` and `azlogs` adapters now, tested against Azurite (Blob) and unit-tested otherwise (P2-8, L45).
- **(b) P2-8 is deferred by implication.**
  - REVIEW.md:3 asks for "one complete, narrow journey rather than a fraction of every subsystem", and REVIEW.md:33 asks only that "The plug-in points ... are ready".
  - R07 rejects the Cosmos layout §6.1.5 was designed on (DR:84-90), and R08 and R09 change idempotency and audit (REVIEW.md:65-67). A Cosmos adapter written now would be written against undecided designs.
  - The journey needs no Cosmos-backed state: every interaction is `effect: "read"`, its delivery is `single` or `chunked`, and nothing is `Metered` (§3.4).
  - Against this: REVIEW.md:5 says "The review does not change requirements by implication".
- **(c) The live tree's reading** (§3). Real adapters only for the ports the journey uses, and with no third-party module. `GW/layers.toml:54-57` writes it down: `[[external]] from = "gateway/adapter/..." allow = []`, with why = "an adapter brings no third-party module of its own; a driver is linked by the deployable". The policy is a file, the audit is JSON lines for a collector, secrets are environment variables, and Snowflake is reached through `database/sql` with the driver linked in `cmd/gateway/drivers.go`.

**AMBIGUOUS / contradiction: reading (c) conflicts with the spec and PLAN.** `layers.toml:54-57` forbids every adapter from importing a third-party module. That conflicts with:
- §6.5.3 (`06-5:107-114`), which gives each adapter its SDK (`azcosmos`, `azblob`, `azsecrets`, `gosnowflake`, MSAL);
- P2-8 (L45);
- PLAN §4's "Real adapter" column (L84-90).

As written, the rule forbids any of P2-8's adapters and a gosnowflake-based `adapter/snowflake` (§6.5.3 L113). Only a `database/sql` adapter with the driver linked in `cmd` gets through. Whoever adopts reading (c) must record it as a departure (AGENTS.md:7, "write the case down").

**RECOMMENDATION.** Record one reading in REVIEW.md, or as A-031 onward in ASSUMPTIONS.md, before step 8. Reading (b) or (c) for the first build fits REVIEW.md:3 and :33. If (c) is kept, record also:
- the policy-file and JSON-lines audit departures (§4);
- the `allow = []` rule, or relax it to let each adapter import its own SDK.

## 5. Defects in the live roots, with evidence

**D-1. The audit fails every call when stdout is a pipe.**
- With `audit_file` unset or `"-"`, `cmd/gateway` passes `os.Stdout` (main.go:101-102).
- `auditlog.Sink.Record` calls `Sync()` on any writer that has it (auditlog.go:70-72), and `*os.File` does.
- `fsync` on a pipe fails. A probe that calls `auditlog.New(os.Stdout).Record(...)` printed:
  - piped (`| cat`): `Record: sync /dev/stdout: bad file descriptor`;
  - to `/dev/null`: `operation not supported by device`;
  - to a regular file: `Record: <nil>`.
  
  It ran with Go 1.25 on macOS/ARM64. The experiment is recorded as historical evidence, not supplied as an executable tool.
- The pipeline turns a failed admission into `unavailable`: "the gateway cannot record the call's admission, so it does not run it" (pipeline.go:245-248).
- So a container, journald or `| tee` deployment refuses every call.
- `auditlog_test.go:16-30` uses a `bytes.Buffer`, so it does not catch this.
- Fix: sync only regular files (`Stat().Mode().IsRegular()`), or require `audit_file`.

**D-2. The policy file defeats the policy-staleness bound.**
- `policyfile.Source.keep` returns the last good policy with a nil error when the file cannot be stat'd, read or parsed (policyfile.go:67-74).
- `pipeline.policyCache.get` then treats the answer as fresh and resets `c.read = now` (pipeline/policy.go:37-41).
- So `PolicyMaxAge` (60 s by default, pipeline.go:68-70) never applies. A deleted or corrupt file keeps deciding by the old policy indefinitely, and nothing is logged.
- This contradicts the port's own contract, "refuses calls when it cannot be renewed in time (R13)" (ports/policy.go:77-79), and ATLAS-CORE:222.
- The policyfile comment says "a bad edit never opens or closes access by accident" (policyfile.go:4-6) and "the pipeline bounds how long it may decide by it (R13)" (:67-68). The second statement is false for this source.
- AMBIGUOUS. Readings: (a) for a file, keeping the last good policy is intended, but must be logged and surfaced in readiness; (b) the source returns the last policy and the error, so the pipeline's bound applies.
- R13 sets no number. The tree's 60 s default matches §6.7's "60-second grant target" (DR:140; ATLAS-MECH-011, `06-7:56`), not §6.1.14's 60 minutes. Record it.

**D-3. A missing cursor key passes silently** (§4, row 7).
- With two replicas, or after a restart, a cursor issued by one is refused by the other with `invalid_request` at `/cursor` (`errCursor`, builtins.go:182). That is a valid cursor refused, which is wrong under ATLAS-MECH-009 (`06-7:54`), whose cases are only another principal, another request, or after an hour.

**D-4. The header limit is 16 KiB where the spec says 64 KiB.**
- `cmd/gateway` keeps `httpserver.Defaults()` `MaxHeaderBytes: 16 << 10` (`REPO/sdk/go/kit/httpserver/httpserver.go:61-72`; main.go:71-78).
- §6.7.15 says "Header bytes: 64 KiB. A person's bearer token with many groups" (`06-7:262-270`).
- Real Entra tokens are what this root verifies.
- Also: `listen` is required in the settings, so `:8080` against the spec's `:8000` depends on the configuration.

**D-5. No `/readyz`.**
- `cmd/gateway` creates `lifecycle.Readiness` and passes it to `httpserver.Run` (main.go:81, :85), but the edge mounts only `GET /healthz` (`GW/edge/edge.go:71`).
- §6.7.15 requires `/readyz` "names each check: ... the audit sink" (`06-7:272`).
- Without it, `ShutdownDelay` cannot drain behind a load balancer. **IN SCOPE** for step 8.

**D-6. Outcome and refusal facts are best-effort.**
- `_ = p.opt.Audit.Record(...)` (pipeline.go:150, :267). Only the admission is durable before dispatch (:245).
- This is consistent with R09 (REVIEW.md:67) and ATLAS-CORE:178. But ATLAS-ACCESS-004 ("refused or not ... durable before the call's answer ends", `06-2:56`) is not met for refusals.
- AMBIGUOUS: whether R09 relaxes refusals too. ATLAS-CORE:182 says "Each attempt, including a replay, refusal or failed authentication, leaves an audit fact".
